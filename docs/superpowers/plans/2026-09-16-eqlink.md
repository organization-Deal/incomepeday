# EQLink boxing integration

User decisions: automatically merge into the existing table; preserve appearance;
include only devices conclusively mapped to existing LO codes. No fuzzy matching
or new EQ rows. Four exact, unique registry matches are configured privately.

## Design

- Worker-only login and fixed-host read APIs. Username, password, public app API
  key and explicit LO/serial mapping are secrets, never frontend configuration.
- Keep GAS rows, names, owners, notes and rename behavior. Replace mapped
  revenue, never add it to the previous source's revenue. Do not create rows.
- EQLink date-range reports use Bangkok calendar dates, THB major units (verified
  vendor currency and frontend currency metadata). One bulk request per day,
  no per-machine request fan-out. Validate currency on every session.
- Daily metadata is separate from original observation slots: closed daily
  totals are not fabricated 22:00 snapshots. Historical statuses retain actual
  GAS observations or UNKNOWN; current device status is used only for the current
  month. Do not derive uptime from sales or project current status into history.
- Replace available 00:00 round revenues with the previous calendar day's total;
  other round revenues are unavailable because EQLink exposes full-day reports,
  not historical intraday snapshots. Keep measured round statuses.
- History replaces mapped monthly totals using bulk date-range reads; GAS keeps
  its recorded uptime. Notes/rename continue to use the same LO identity.
- Atomic reads: a failed, truncated, duplicate or malformed EQLink report fails
  the request through the existing error surface. No fabricated zeros or stale
  success. Bound each report to 100 devices, verify count; reject larger fleets
  until a pagination/subrequest budget is provisioned. Maximum 31 daily reports,
  login + currency + device list (34 outbound calls), concurrency four and a
  shared 40-second deadline. No automatic retry or persistent token storage.
- Cache merged monthly data under a mapping/config fingerprint (SHA-256); changing
  secrets cannot reuse an old account's data. Fresh bypasses cache. Current month
  cache 10 minutes, historical six hours, matching existing behavior.

## Verification / rollout

1. Synthetic tests: mapping uniqueness, units, dates/leap/month boundaries,
   zero versus missing, pagination overflow, failures, bounded concurrency,
   replacement totals, current versus historical status and secret redaction.
2. Browser: preserve baseline pixels with integration disabled; verify merged
   day/week/month and status/filter/CSV behavior with synthetic source data.
3. Private live read: reconcile daily sums to whole-range report for four mapped
   devices. No machine controls, money movement or production data writes.
4. Review diff, test, dry-run bundle, update draft PR. Production enablement
   requires Worker secrets and deployment; do not claim deployment from a PR.
